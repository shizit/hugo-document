### 1. WPA

WPA（Wi-Fi Protected Access）は、  
無線LAN（Wi-Fi）の通信を保護するためのセキュリティ規格です。  
従来利用されていたWEPに脆弱性が発見されたことを受け、  
Wi-Fi Allianceによって2003年に導入されました。

WPAでは、WEPの問題を改善するため、以下の仕組みが導入されています。

* IEEE 802.1X / EAPによる認証
* 暗号鍵の動的な生成・更新
* TKIP（Temporal Key Integrity Protocol）による暗号化
* MIC（Message Integrity Check）による改ざん検知
* リプレイ攻撃への対策

---

### 2. Wi-Fiセキュリティ規格の変遷

Wi-Fiのセキュリティ規格は、以下のように発展しています。

```text
WEP
 ↓
WPA
 ↓
WPA2
 ↓
WPA3
```

#### 2.1 WEP

WEP（Wired Equivalent Privacy）は、  
無線LANの通信を暗号化するために初期に広く利用された方式です。  
WEPでは、RC4を暗号アルゴリズムとして使用し、  
WEPキーとIV（Initialization Vector）からRC4の鍵を生成します。

```text
WEPキー（秘密）
      ＋
IV（公開・24ビット）
      ↓
RC4の鍵
      ↓
RC4
      ↓
暗号化
```

##### WEPの問題点

WEPには以下の問題があります。

* WEPキーが基本的に固定される
* IVが24ビットと短い
* IVが通信データとともに送信されるため、第三者から確認できる
* IVの再利用が発生する可能性がある
* RC4の鍵生成に関する弱点がある
* 特定のIVでは、暗号化に利用される情報に偏りが生じる

そのため、大量の通信を収集して分析することで、WEPキーを推測できる場合があります。

特に、

```text
IVが短い
   ＋
IVが公開される
   ＋
RC4の鍵生成に弱点がある
   ↓
通信データを大量に収集
   ↓
WEPキーに関する情報を分析
   ↓
WEPキーを推測
```

という点がWEPの大きな問題となりました。

##### WEPキー

WEPキーは、通信の暗号化に使用する秘密鍵です。  
アクセスポイントと端末に同じWEPキーを設定して使用します。  
WEPキー自体は通信中に送信されませんが、  
基本的に同じキーを長期間使用するため、  
暗号化された通信データが蓄積されることが問題となります。

##### IV

IV（Initialization Vector）は、暗号化処理に変化を与えるための値です。  
WEPでは24ビットのIVを使用します。

```text
WEPキー ＋ IV
      ↓
RC4の鍵
```

IVは通信データとともに送信されるため、第三者から確認できます。  
また、24ビットと短いため、通信量が増えると同じIVが再利用される可能性があります。

##### RC4

RC4は、WEPで使用されたストリーム暗号方式の暗号アルゴリズムです。  
WEPでは、WEPキーとIVからRC4の鍵を生成し、  
その鍵からキーストリームを生成してデータを暗号化します。

```text
WEPキー ＋ IV
      ↓
RC4の鍵
      ↓
キーストリーム生成
      ↓
データと組み合わせて暗号化
```

RC4には、特定の鍵条件で暗号化に使用される情報に偏りが生じる問題があります。  
WEPではIVをRC4の鍵の一部として使用していたため、  
この問題がWEPの脆弱性につながりました。

---

#### 2.2 WPA

WPAは、WEPからWPA2への移行をつなぐ暫定的なセキュリティ規格として  
2003年に導入されました。  
既存のWEP対応機器でも導入しやすいよう、  
WEPで使用されていたRC4を継続して利用しながら、  
鍵管理やデータの完全性を改善しています。

WPAでは、主に以下の仕組みを使用します。

* IEEE 802.1X / EAP
* 4-Way Handshake
* TKIP
* RC4

特に、TKIPによってWEPの固定的な鍵利用や完全性保護などの問題が改善されています。

---

#### 2.3 WPA2

WPA2は、IEEE 802.11iの仕様をベースとして2004年に導入されました。  
WPAで使用されていたTKIPに加えて、  
より強力な暗号方式であるAES-CCMPが標準的に使用されます。

```text
WPA
 ↓
TKIP / RC4

WPA2
 ↓
AES-CCMP
```

WPA2では、WPAで導入された認証・鍵交換などの仕組みを引き継ぎながら、  
通信の暗号化方式をAES-CCMPへ移行しています。

---

#### 2.4 WPA3

WPA3は、WPA2の後継となるWi-Fiセキュリティ規格です。  
WPA2で使用されていた仕組みをさらに発展させ、  
認証や通信保護に関するセキュリティを強化しています。

Wi-Fiセキュリティ規格の位置付けは、以下のようになります。

| 規格   | 概要                   |
| ---- | -------------------- |
| WEP  | 初期の無線LAN暗号化方式。現在は脆弱  |
| WPA  | WEPの問題を改善した暫定規格      |
| WPA2 | WPAを発展させ、AES-CCMPを採用 |
| WPA3 | WPA2の後継。認証などをさらに強化   |

---

### 3. WPAの基本構成

WPAによる通信保護は、以下の処理に分けて整理できます。

1. 認証
2. 暗号鍵の生成
3. データの暗号化
4. データの完全性確認
5. リプレイ攻撃への対策

---

#### 3.1 認証

Wi-Fiへ接続する端末がネットワークを利用できるかを確認します。  
WPAでは、利用形態に応じて主に以下の2方式があります。

##### WPA-Personal

家庭や小規模なネットワークで利用される方式です。  
アクセスポイントと利用者の間で事前共有した秘密情報を使用します。

```text
利用者
  ↓
共有パスワード
  ↓
アクセスポイント
```

この共有情報をPSK（Pre-Shared Key）と呼びます。

---

##### WPA-Enterprise

企業などのネットワークで利用される方式です。  
IEEE 802.1XとEAPを利用し、認証サーバーを介してユーザーを認証します。

```text
端末
 ↓
アクセスポイント
 ↓
認証サーバー
```

ユーザー単位で認証を行えるため、企業ネットワークなどで利用されます。

---

### 4. WPAの通信保護

認証後、通信に使用する暗号鍵を確立し、実際のデータを暗号化します。

```text
送信データ
   ↓
暗号化
   ↓
暗号化されたデータ
   ↓
無線通信
   ↓
復号
   ↓
元のデータ
```

WPAでは、主にTKIPを使用して通信を保護します。

---

### 5. TKIP

TKIP（Temporal Key Integrity Protocol）は、  
WPAで採用された通信保護プロトコルです。  
WEPとの互換性を考慮し、RC4を利用しながら、  
鍵管理やデータの完全性を改善しています。

#### 主な特徴

* パケットごとの暗号鍵生成
* 暗号鍵の更新
* MICによる改ざん検知
* リプレイ攻撃への対策
* RC4をベースとした暗号化

---

#### 5.1 パケットごとの鍵生成

WEPでは、基本的に同じWEPキーを長期間使用します。  
TKIPでは、パケットごとに異なる暗号鍵を生成します。

```text
パケット1 → 鍵A
パケット2 → 鍵B
パケット3 → 鍵C
パケット4 → 鍵D
```

これにより、同じ暗号鍵を繰り返し使用することによる問題を軽減します。

---

### 6. AES-CCMP

AES-CCMPは、WPA2で標準的に使用される通信保護方式です。  
AESとCCMPという2つの要素から構成されます。

#### 6.1 AES

AES（Advanced Encryption Standard）は、  
データを暗号化するための共通鍵暗号アルゴリズムです。  
暗号化と復号に同じ秘密鍵を使用します。

#### 6.2 CCMP

CCMP（Counter Mode with Cipher Block Chaining Message Authentication Code Protocol）は、  
AESを利用して通信の機密性と完全性を保護するプロトコルです。  
暗号化だけでなく、通信データが改ざんされていないことの確認にも利用されます。

---

### 7. TKIPとAES-CCMP

| 項目       | TKIP             | AES-CCMP     |
| -------- | ---------------- | ------------ |
| 主な利用規格   | WPA              | WPA2         |
| 暗号アルゴリズム | RC4              | AES          |
| 暗号方式     | ストリーム暗号          | ブロック暗号       |
| 完全性保護    | MIC              | CCMP         |
| 位置付け     | WEPからの移行を目的とした方式 | WPA2の標準的な方式  |
| 現在の位置付け  | 古い方式             | 現在も広く利用される方式 |

WPAとWPA2の大きな違いは、通信保護に使用する暗号方式です。

```text
WPA
 ↓
TKIP
 ↓
RC4

WPA2
 ↓
AES-CCMP
 ↓
AES
```

---

### 8. WPAとWPA2の関係

WPA2は、WPAで導入された認証や鍵交換などの仕組みを発展させた規格です。

```text
WPA
├── 802.1X / EAP
├── 4-Way Handshake
├── TKIP
└── RC4

        ↓ 発展

WPA2
├── 802.1X / EAP
├── 4-Way Handshake
├── AES
└── CCMP
```

WPAからWPA2への移行では、  
特に通信の暗号化方式がTKIP/RC4からAES-CCMPへ変更された点が重要です。

---

### 9. WPAによる通信開始までの流れ

WPA-Personalを例にすると、通信開始までの流れは以下のようになります。

```text
┌─────────┐                 ┌─────────────┐
│  端末   │                 │アクセスポイント│
└────┬────┘                 └──────┬──────┘
     │                             │
     │      Wi-Fi接続要求          │
     ├────────────────────────────>│
     │                             │
     │      認証・鍵交換           │
     │<───────────────────────────>│
     │                             │
     │      暗号鍵を確立           │
     │                             │
     │      暗号化データ           │
     ├────────────────────────────>│
     │                             │
     │      暗号化データ           │
     │<────────────────────────────┤
```

ここで、Wi-Fiのパスワードをそのまま通信データの暗号化に使用するわけではありません。  
認証および鍵交換を行った上で、  
実際の通信に使用する暗号鍵を確立します。

---

### 10. まとめ

Wi-Fiのセキュリティ規格は、  
WEPの問題を解決する形で発展してきました。

```text
WEP
 │
 │ RC4 / 24ビットIV
 │
 │ 脆弱性
 ↓
WPA
 │
 │ TKIP / RC4
 │ 鍵管理・完全性保護を改善
 ↓
WPA2
 │
 │ AES-CCMP
 │ より強力な暗号方式
 ↓
WPA3
 │
 │ 認証・通信保護をさらに強化
```

WEPの問題を理解する上では、**WEPキー、IV、RC4の関係**が重要です。

```text
WEPキー
   ＋
IV
   ↓
RC4の鍵
   ↓
RC4
   ↓
暗号化
```

WPAではWEPの問題を改善するためにTKIPが導入され、  
WPA2ではAES-CCMPへ移行しました。
